How monctl flip decides

Why Flip Monitor went one-way after m1ddc 1.3.1, and the fix (tds-utils Issue#817).

The pieces

Flip Monitor.app-> monctl flip-> m1ddc display 2 get input-> DDC/CI over the Thunderbolt cable-> Dell U2725QE, VCP 0x60

The app shows monctl's output as a notification, and a non-zero exit as a "failed" notification. monctl finds the panel by name each run, reads its current input, then sets the other one.

What changed: how m1ddc decodes the reply

m1ddc 1.2.0 (what monctl was written against, 2026-08-08)
..bytes 0-7
0x19SH
0x19SL
Reads one byte, SL. Thunderbolt reads 25.
m1ddc 1.3.1 (Homebrew, 2026-11-06)
..bytes 0-7
0x19SH
0x19SL
Reads two bytes, SH and SL. Thunderbolt reads 6425 (0x1919).

For VCP 0x60 the input is SL. The Dell fills SH with 0x19 on both inputs, so the DisplayPort state now reads 6415 (0x190F).
