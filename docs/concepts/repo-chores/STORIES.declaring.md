# Stories: declaring

A repo writing its chores down, next to its code.

- As a repo author, I can put a chore definition in my repo's `.chores/`
  and have it travel with the repo, reviewed and versioned like the code
  it looks after.
- As a repo author, I can write a repo chore in the same shape as any
  other chore, so nothing new has to be learned to write one.
- As a repo author, I can see, before I commit, whether my repo's chores
  are valid.
- As a repo author, I can say what my chore needs -- backend, budget,
  schedule -- and know the operator decides whether it gets it.
- As an operator, I can keep defining chores for my own machine outside
  any repo, exactly as today.
- As an operator, I can tell a repo chore from a machine chore at a
  glance, and see which repo it came from.
