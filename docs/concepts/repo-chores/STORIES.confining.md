# Stories: confining

A repo chore staying in its repo's lane.

- As an operator, I can be certain a repo chore works on its own repo and
  cannot reach another repo on my machine.
- As an operator, I can be certain a repo chore cannot touch my machine's
  own chores, their definitions, their records, or the kill switch.
- As an operator, I can be certain a repo chore cannot grant itself a
  credential, a backend or a budget I did not accept.
- As an operator, I can see what a repo chore is allowed to touch before
  I accept it.
- As an operator, I can stop every chore from one repo without touching
  any other repo's chores.
- As an operator, I can cap what one repo's chores may spend in total, so
  one repo cannot drain the herd.
- As a repo chore, I cannot change my own definition into one that runs
  without a human accepting it.
