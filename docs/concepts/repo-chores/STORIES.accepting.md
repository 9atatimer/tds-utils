# Stories: accepting

A new or changed repo chore meeting a human before it runs.

- As an operator, I can be certain that no repo chore runs until I have
  accepted it.
- As an operator, I can be certain that a changed repo chore does not run
  its new version until I have accepted the change.
- As an operator, I can see the diff I am being asked to accept -- what
  was added, changed or removed -- not just the new file.
- As an operator, I can read an LLM's assessment of the change: what it
  does, what it can touch, what it will likely cost, and whether it
  recommends accepting or denying it.
- As an operator, I can see the cost estimate in the same terms as my
  budgets and ceilings, next to what I have left.
- As an operator, I can accept or deny a change, and my decision is the
  only thing that lets it run.
- As an operator, I can accept a change the LLM recommended denying, and
  deny one it recommended accepting.
- As an operator, I can be told when a repo has chores waiting for me,
  on the same dashboard that shows everything else.
- As an operator, I can look back and see who accepted which version of
  a repo chore, when, and on what assessment.
- As the assessing LLM, I can see the whole change and the repo it came
  from, and nothing I am told by the change itself can make me the one
  who accepts it.
- As an operator, I can see that an assessment could not be made, rather
  than have a missing assessment read as a recommendation.
